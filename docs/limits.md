# Known limits and trade-offs

Every limit of Tracekit is written down next to the feature it belongs to, which makes it easy to miss when you read
only one page. This page collects them in one place. Each release's notes link here, and a doc that adds a "Limits"
section must be linked from this page (`tests/test_docs.py` checks it).

Each row says what the limit is, why it is so, what to do about it, and where the details are. Rows marked
**(1.1)** describe behaviour new in 1.1, not in 1.0; **(1.2)**, new in 1.2; **(1.3)**, new in 1.3.

What Tracekit guarantees and doesn't, per deployment, on one page: [guarantees](guarantees.md).

## Evidence and verification

| Limit | Why it is so | What to do | Details |
|---|---|---|---|
| A verified bundle doesn't prove intent. | A record says a call was made, not why. | Read decisions, approvals and reasons alongside the records. | [FAQ](faq.md#what-cant-tracekit-prove) |
| A verified bundle doesn't prove that everything the agent did was recorded. | An action that crosses no capture layer (a subprocess, code that skips the adapter, a call around a gateway that isn't mandatory) leaves no record. **(1.2)** What some layer saw and nothing reported is now a signed gap: a call allowed or approved that never completed (`decided_not_completed`), a tool result the gateway saw go back with no decide (`reconcile.hook_missing`, at once), client counter values never received (`client_counter_gap`, also at `close_run`), writes after `run.final` (`late_activity`), a second run from inside a bound harness process (`concurrent_run`), a tailer that stops (`tailer_lost`) and a second tailer token for a run (`tailer_redelegated`). A call no layer saw still leaves nothing. | Read the `coverage`, `tiers` and gap lines; add an out-of-process layer (the [LLM gateway](gateway.md), the [tool executor](executor.md), the [MCP gateway](mcp-gateway.md)). | [FAQ](faq.md#what-cant-tracekit-prove), [verdicts](verdicts.md#informational-lines-always-pass) |
| A verified bundle doesn't prove that a tool result the agent reported is true. | In-process capture (T1) records what the agent's process reported; only out-of-process capture (T2) sees what crossed a boundary. | Prefer T2 evidence for calls that matter; use `executor: t2` approvals. | [FAQ](faq.md#what-cant-tracekit-prove), [approvals](approvals.md#tiers-t1-and-t2-executors) |
| A `tool.result`'s `output.size` is the size of what the signer received. For a tool whose result the adapters send as its digest (every tool the policy doesn't list as untrusted), that is the digest's size, not the result's. | The signer records what it can check; a size the client claimed would be the agent's word. | Read `output.size` as the size of the content committed to; list a tool under `untrusted:` to have its result itself sent, redacted and committed to. | [privacy](privacy.md) |
| Imported OpenTelemetry (T3) proves only that spans were received. | Spans are exported after the work is done, by the application. | Gate calls with an adapter or hook; treat T3 runs as a log, not evidence of completeness. | [OpenTelemetry](otel.md#receiving-traces-tier-t3-import) |
| Tracekit is tamper-evident, not tamper-proof: a deletion shows, it isn't prevented. | Prevention would need attested hardware (a TEE), which Tracekit doesn't claim. | Keep independent witnesses and a monitor so a rewrite is detected. | [FAQ](faq.md#what-cant-tracekit-prove) |
| Whoever holds the signer's key can rewrite or fork its log; nothing in the bundle alone shows it. | Signatures prove who signed, not that the key holder didn't sign again. | Pin a witness the operator doesn't run (`witnessed`) and a monitor (`witnessed+monitored`). | [server threat model](threat-model-server.md#s4-the-operator-organisation-and-the-exporter) |
| Records after the last cosigned checkpoint are unproven. | A witness vouches only for what it has cosigned. | Export after the next checkpoint; read the `log tail` warning. | [verdicts](verdicts.md#warnings---strict-exits-3), [witnesses](witnesses.md#trust-model-per-witness-type) |
| A bundle exported before its run is finalised verifies only `TO HEAD n (open)`. | The signer finalises a run a few seconds after it closes. | Re-export after `run.final`; for audits require `VERIFIED`. | [quickstart](quickstart-v2.md#export-and-verify-by-hand), [verdicts](verdicts.md#integrity) |
| A single run's bundle doesn't show that no other run was left out. | The exporter chooses which runs to export. | Ask for the tenant's run-set bundle and require `run-set: COMPLETE`. | [auditor guide](auditor-guide.md#3-get-the-bundles) |
| A withheld key retirement isn't visible unless a run-set from registry size 0 reaches the bundle. A bundle whose key records show one key and no retirement says so only on its `Assurance` line, not as a warning: a retirement withheld together with its new key would look the same. | Only the registry log proves which `key.retire` records exist. | Read `key retirements not proven complete` on the `Assurance` line (a `keys` warning when the key records show a retired key); require a run-set from registry size 0 where it matters. | [verdicts](verdicts.md#warnings---strict-exits-3) |
| `key assurance` is `asserted` unless a record-key issuer certifies the keys. | Without an issuer the log declares its own record keys. | Run an [issuer](issuer.md) and pin it in the trust config. | [issuer](issuer.md#verifying) |
| The verifier doesn't fetch revocations. | Verification is offline and takes trust only from the verifier's side. | Pass the issuer's log with `--revocations`. | [issuer](issuer.md#limits) |
| A trust config the operator supplies proves nothing about the operator. | The bundle carries no code or trust (I9); whoever writes the trust config decides what verifies. | Build `trust.json` from independent sources and install the verifier yourself. | [auditor guide](auditor-guide.md#2-build-the-trust-config-from-independent-sources) |
| A v1 bundle verified without `--key` or `--witness` is only internally consistent (`UNANCHORED`). | A bundle carries its own public key, so a bundle forged with a fresh key is consistent too. | Pin the signer's key or an independent witness. | [laptop threat model](threat-model-laptop.md#trust-roots-for-verification) |
| v1: the exporter can replace a selected record with an elided stub, and `manifest.json` is unsigned. | v1 stubs are not bound to a run; the manifest is an index, recomputed from signed records. | Use v2 bundles; read the "run completeness unproven" warning. | [laptop threat model](threat-model-laptop.md#open-problems) |
| Record timestamps come from the signer host's clock; `seq` and the chain prove order only. | Only witnesses and RFC 3161 timestamps give independent time. | Read cosignature and anchor times in the `Assurance` line. | [laptop threat model](threat-model-laptop.md#what-each-attack-comes-to), [witnesses](witnesses.md#v2-rekor-v2-anchors-and-rfc-3161-timestamps) |
| A v1 record after a v1 → v2 bridge is reported only with `--v1-ledger`. | The frozen v1 verifier sees bridge records as ordinary gaps. | Verify bridged logs with `--v1-ledger`. | [format v2](format-v2.md#12-v1--v2-bridge) |
| The TypeScript verifier reports `UNVERIFIABLE` for bundles that rely on a Rekor anchor, an SLH-DSA checkpoint signature or certified record keys. | Web Crypto has no SLH-DSA, and those checks aren't ported yet; it never says `VERIFIED` for a check it skipped. | Verify such bundles with the Python verifier (`pip install tracekit-ai`). | [auditor guide](auditor-guide.md), [format v2](format-v2.md#13-implementations) |
| The TypeScript verifier needs Node 20.12 or newer (or a current browser). | It uses JSON imports and `DecompressionStream("deflate-raw")`, which earlier Node 20 releases lack. | Upgrade Node, or use the Python verifier. | [TypeScript SDK](../sdk/typescript/README.md) |
| `npx @cygnuxlabs/tracekit verify` with `--monitor-report`, `--revocations` or the v1 bridge options runs the Python verifier, which must be installed. | Only the Python verifier has those checks. | `pip install tracekit-ai`, or verify without those options. | [auditor guide](auditor-guide.md) |
| **(1.2)** A bundle holding a run started by another run (`parent_run`, a sub-agent's run) needs tracekit 1.2 or newer; a 1.1 verifier reports it `UNVERIFIABLE (needs tracekit >= 1.2.0)`. | Every v2 record definition is closed, so an older verifier can't read the new fields; the manifest's `verifier_min_version` makes it say so instead of `FAILED`. | Verify with tracekit 1.2 or newer (Python or TypeScript). | [format v2](format-v2.md#9-bundle-layout) |
| **(1.2)** A bundle holding a 1.2 completeness gap (`decided_not_completed`, `late_activity`, `concurrent_run`, `tailer_redelegated`, a gap's `run_id`), a `run.child` record or a run.final with `provider_executed` needs tracekit 1.2 or newer; older verifiers report it `UNVERIFIABLE (needs tracekit >= 1.2.0)`. | The new kinds and fields are outside the 1.1 schema; the manifest's `verifier_min_version` says so. | Verify with tracekit 1.2 or newer. | [format v2](format-v2.md#9-bundle-layout) |
| Experimental surfaces may change between releases and get less hardening than the stable core. | Few people run them yet; the stable core is what is tested end to end and fixed first. | Build on the stable core; each experimental command or server says so on stderr when it starts. | [what's stable](support.md) |
| JSON nested deeper than 128 levels is refused: a bundle file is unusable, a record fails, and a tool call's arguments are denied (`TK-ARGS-INVALID`). | A fixed depth makes every verifier and the signer read the same documents the same way, whatever their parser's limits. | Flatten arguments deeper than that. | [format v2](format-v2.md#1-canonical-json) |

## Dev mode vs system mode

| Limit | Why it is so | What to do | Details |
|---|---|---|---|
| **v1 tracekitd:** witness publishing (git push, HTTP) runs under the signer's lock, so an unreachable witness stalls appends for up to 15–60 s; a local user can hold the 64 connections by trickling bytes (the dev socket is world-writable); `runs.json` is rewritten on every append. | The v1 daemon is single-writer and laptop-sized. | Use the v2 signer for anything shared or busy; keep v1 witnesses reachable. | [laptop threat model](threat-model-laptop.md) |
| **v1 tracekitd:** a restart takes every run of the ledger as active again, so past the run cap it writes `run_state_evicted` gaps for long-finished runs, and a run that never sent `run.start` loses its owner. Parallel hooks of one session can record a false `trace.tamper` (transcript length read before the send). Client state files (`~/.tracekit-client/runs/`, Gemini call ids, transcript acks) are never pruned. | v1 state is rebuilt from the ledger and kept per laptop. | Read those gaps as restart artefacts; prune `~/.tracekit-client/runs/` by hand. | [laptop threat model](threat-model-laptop.md) |
| Same-user dev mode protects nothing against the agent itself. | The dev signer runs as your user, so an agent that runs commands as you can read its key, stop it, or rewrite and re-sign its store. Policy rules (`TK-D007`, `TK-D013`) are tripwires. | Use system mode, a sidecar or a central signer for anything you need to rely on; dev bundles say `isolation: same-user`. | [FAQ](faq.md#what-does-same-user-dev-mode-protect), [quickstart](quickstart-v2.md#what-dev-assurance-means) |
| `Assurance` describes checkpoint cosigning, not isolation: a same-user signer with a witness verifies as `witnessed`. | The two are independent properties. | Read `isolation` as well as `Assurance`. | [verdicts](verdicts.md#assurance), [witnesses](witnesses.md#v2-c2sp-tlog-witnesses) |
| A system-mode signer without a witness verifies as `Assurance: dev`. | Nothing outside the host shows the log wasn't rolled back. | Add a witness on another host that the operator doesn't run. | [deployment](deploy.md#what-decides-a-bundles-assurance) |
| System mode doesn't protect against root on the machine. | Root can read the key and rewrite the store. | Witnesses on another host detect a rewrite of what they cosigned. | [deployment](deploy.md#laptop-system-mode) |
| In system mode the agent can remove the hook from its own `~/.claude/settings.json`, or act outside Claude Code, with no record and no gap. | The hook lives in the agent user's settings. | Use admin-managed settings (`init --managed`, v1) or an out-of-process record (gateway). | [quickstart](quickstart-v2.md#system-mode-linux-macos-experimental) |
| v1 system mode (`sudo tracekit init` without `--v2`) has no uninstall: `tracekit uninstall` takes the hooks out of user and project settings only, not out of admin-managed settings (`--managed`), and leaves tracekitd's service, `/var/lib/tracekit`, `/opt/tracekit` and `/etc/tracekit/client.json`. | v1 system mode is the legacy path; `sudo tracekit uninstall --v2` removes v2 system mode. | Remove Tracekit's hook groups from the managed settings file, stop and remove the tracekitd unit (or launchd plist), then those paths. | [quickstart](quickstart-v2.md#system-mode-linux-macos-experimental) |
| Without harness binding, any process of the agent's user can write into the agent's runs or start runs of its own. | The signer knows the caller by uid; run tokens are readable by that uid. | Register the harness (`--harness`, Linux). | [quickstart](quickstart-v2.md#system-mode-linux-macos-experimental) |
| System mode requires an agent user that is not root and not in a sudo, wheel, admin, docker or similar group. | Such a user could take over the signer. | `tracekit doctor` (`D-AGENT-PRIV`) checks it. | [doctor](doctor.md#v2-checks) |
| When the transcript tailer's ACL or sudo rule can't be set up, every run records a `tailer_lost` gap instead. | The tailer needs read access to the agent's transcripts. | Fix the setup init reports. | [deployment](deploy.md#laptop-system-mode) |

## Signer and capture

| Limit | Why it is so | What to do | Details |
|---|---|---|---|
| A tool class set to fail `open` runs unrecorded while the signer is down. | It is the setting you choose when an outage must not stop the agent; the next call writes a signed gap for exactly the missed calls. | Keep `fail_modes` closed (the default); the report warns on every fail-open class. | [FAQ](faq.md#what-happens-when-the-signer-is-down) |
| While the signer is unreachable, the LangChain adapter and the Claude Code hook pick a call's fail mode by the class the shipped default policy gives the tool (`terminal` is `shell`, an unmapped tool `unknown`); the MCP and Browser Use adapters by their fixed class (`mcp`, `browser`); the OpenAI Agents, Claude Agent SDK and CrewAI adapters apply `default` to every tool. A signer whose policy maps the tool to another class may have another fail mode for it. | The tool's class is the signer's decision, and the signer can't be asked. | Keep fail modes closed for classes your policy remaps, or set `default`; with OpenAI Agents, the Claude Agent SDK or CrewAI, set `default`. | [FAQ](faq.md#what-happens-when-the-signer-is-down) |
| Model calls (autotrace) while the signer is down: under a closed `model` fail mode a request that can't be recorded is refused (`PermissionError`, saying so and what to do); a response the signer missed (it went down mid-call) is sent again at the next model call or at exit, after a signed `client_counter_gap` for the try that failed. A signer that stays down until the process exits leaves the request without its response, and the run open until the signer's idle timeout. | The client records only while the signer answers, and keeps missed responses in memory (the newest 1024). | Keep the signer running (system mode restarts it); set `fail_modes: {model: open}` to let model calls run unrecorded during an outage. | [FAQ](faq.md#what-happens-when-the-signer-is-down) |
| v1 coding-agent hooks allow a call when the payload can't be parsed or the harness is unknown. **(1.2)** v2 hooks that `tracekit init` wrote from 1.2 on name their event, so a pre-tool payload that can't be parsed is blocked; a post-tool one is reported on stderr, and the call it ends is completed as an error at the session's next Stop, prompt or end. v2 hooks installed before 1.2 still let an unparseable payload through, unrecorded; `tracekit doctor` (`D-HOOKS-EVENT`) finds them for Claude Code only. | Broken input never blocks an agent in v1. A hook that can't parse its payload knows its event only from the command line. The harness writes the payload, not the agent. Doctor reads only Claude Code's settings. | Re-run `tracekit init` after upgrading (`--agent NAME` for Codex, Cursor and Gemini CLI, which doctor doesn't check); in v1 set `TRACEKIT_FAIL_CLOSED=1` or `fail_mode: closed`. | [coding agents](coding-agents.md#hooks-name-their-event-12), [doctor](doctor.md#v2-checks) |
| The signer can't tell a real event from a well-formed fake sent by the agent's identity. | Anything that can call the signer as the agent can submit plausible events. | Cross-check with an independent layer: the gateway (`gateway_mandatory`) or, in v1, the model proxy. | [laptop threat model](threat-model-laptop.md#two-properties-kept-apart), [signing](signing.md#what-the-signer-checks-before-signing) |
| Compromised application code can skip the adapter for some calls, and suppress in-process autotrace (L3) too. | Both run in the agent's process. | Run the LLM gateway outside the agent; read `reconcile.*` and `(L3 absent)` in the report. | [server threat model](threat-model-server.md#s2-compromised-application-code) |
| Capture layers L4 and L5 are not shipped; **(1.2)** L6 (network) is the [egress observer](egress.md), hosts only. | Out-of-process capture of processes and services isn't built yet; the coverage matrix says `not covered` for them. | Use the [LLM gateway](gateway.md), the executor and the egress observer as the out-of-process records. | [server threat model](threat-model-server.md#known-limits) |
| SDK and adapter capture is opt-in per call: only wrapped calls are seen and gated. | An adapter sees only the calls routed through it. | Wrap every tool; each integration lists what it doesn't cover. | [laptop threat model](threat-model-laptop.md#two-properties-kept-apart), [OpenAI Agents](integrations/openai-agents.md#not-covered), [MCP](integrations/mcp.md#not-covered), [Browser Use](integrations/browser-use.md#not-covered), [Claude Agent SDK](integrations/claude-agent-sdk.md#not-covered), [CrewAI](integrations/crewai.md#not-covered), [Pydantic AI](integrations/pydantic-ai.md#not-covered) |
| Actions inside subprocesses and background processes, and faked command output, aren't observed. | Only the command line is seen; tool results are what the harness reports. | OS-level capture (a sandbox, audit) is outside Tracekit. | [laptop threat model](threat-model-laptop.md#open-problems) |
| Nothing is recorded after the session's last hook, including transcript edits. | Nothing runs to see it. | Treat the run's end as the last observed point. | [laptop threat model](threat-model-laptop.md#open-problems) |
| **(1.2)** `decided_not_completed` is written at `run.final` only, and doesn't say why the result never came (the agent stopped or crashed, its post-call hook didn't run, or a client dropped it). Calls denied, or asked and never approved, get none: they may not run; a call the executor or a gateway holds gets `held_call_unresolved` instead. A decision is also exempt when a later decision of the same call completed, except one whose approval was consumed and whose call didn't complete with the approved arguments; only the call's latest decision counts as later, so an open decision before a completed one and an open one after it is a gap too. | The signer sees the decide and the missing `complete`, not the agent or the harness's prompt. At most 100 per run are listed, then one gap counts the rest. | Read the gap next to the run's other records and the transcript or app log; a crash usually ends the run early too. | [coding agents](coding-agents.md#what-the-signer-records-as-a-gap-12) |
| **(1.2)** A coding-agent hook completes each call that got no post-tool event (declined in the harness's own permission prompt, interrupted, or a post-tool payload it couldn't read) as an error when the session ends. That result is the hook's word, not the harness's; a session killed before its end event leaves such calls as `decided_not_completed` gaps instead. | No hook event says that a call was declined or interrupted, and a background sub-agent's call can still run when a turn ends; the session's end is the first point where none can. | Read a `tool.result` error "no PostToolUse came" as "not seen to run". | [coding agents](coding-agents.md#what-the-signer-records-as-a-gap-12) |
| **(1.2)** `concurrent_run` covers only runs bound to a harness process (harness binding, Linux system mode): a second run started from inside the same harness process while another session's run is open there, once both have recorded an event since it registered. SDK and server runs, which run several at once by design, and harnesses without binding get no such check. A run started with `parent` (a sub-agent's) gets none either: the agent can read its session's run token, so a second session can pose as a child, and shows only as a `run.child` record in the parent. Which runs overlap is kept in memory and snapshots: a signer restart with no snapshot since forgets a pending one. | One harness process drives one session at a time; without a binding the signer can't tell a forged second run from a legitimate parallel one, and an older session's run left open and idle is no overlap. | Turn on harness binding for coding agents; pass `parent` for a sub-agent's run; read each `run.child` against the harness's transcripts. | [format v2](format-v2.md#3-events) |
| **(1.2)** A killed transcript tailer is a `tailer_lost` gap only in system mode, once it has made no call (heartbeat or record) for 90 s while the run is open, counted from when the hook took its token, and only while the signer runs: the watch is kept in memory. In dev mode the tailer runs as the agent's user, which may not send heartbeats, so a killed tailer leaves no gap. Heartbeats show that a process holding the run's tailer token is alive, not that it reads the session's real transcript: the agent's user starts the tailer (through sudo) and names its transcript, so it can stop the real one and start one of its own on a file it writes. A second tailer token for the run is a `tailer_redelegated` gap, but a decoy handed the first token (the agent's user can read the hook's memory) isn't. A tailer that keeps its heartbeats but stops reading is caught only by its idle limit. | The signer can't watch the tailer's process or see the transcript; the heartbeat is its only signal, and only an identity the agent doesn't control may send it. | Use [system mode](deploy.md#laptop-system-mode) (`sudo tracekit init --v2`) where a killed tailer must show; compare the run's transcript records with the transcript itself where it matters; re-check runs that span a signer restart. | [coding agents](coding-agents.md#what-the-signer-records-as-a-gap-12) |
| **(1.2)** Writes refused because their run is final are counted per run in memory and written about once a minute as a `late_activity` gap in the tenant's signer run; counts since the last write are lost if the signer stops uncleanly. A `close_run` never counts, nor does the first write of each identity and stream (up to 64 per run): a client learns from it that its run ended, after an idle close, and moves to a new run. A run-set lists them with the tenant-level gaps. | The writes can't go into a final run, and the signer-level refusal summary doesn't name the run. | Read `late_activity` in a run-set; if it recurs, check that each client registers a new run once its run ends. | [format v2](format-v2.md#3-events) |
| **(1.2)** Trailing client counter values become a gap only when the client says where its stream ended (`close_run` `last_client_seq`), and only for streams the closing identity wrote (or that never reached the signer); after a signer restart with no snapshot since, a stream written before it can't be ended that way. The LLM gateway says so when it drops a run from memory or stops (SIGTERM or Ctrl-C; a killed gateway says nothing); for a run already final the gap goes in the tenant's signer run, naming the run. A gateway whose identity lacks the `close_run` grant logs the refusal on stderr and leaves no gap. | The signer can't know of values a client never sent, so the gap is the closing identity's word, and its reason names that identity; values up to there that still arrive in the grace period are recorded with no second gap. | Close runs with `last_client_seq` from your own clients; grant gateways `close_run` and stop them with SIGTERM; read a gap's reason for who reported it. | [gateway](gateway.md#what-is-recorded) |
| **(1.2)** A live `reconcile.hook_missing` (written mid-run, for a detector) comes from the LLM gateway's records only; agent-reported L3 is still reconciled at `run.final`. | Agent-reported L3 comes from the process being checked. | Run the gateway for calls that matter. | [gateway](gateway.md#what-is-recorded) |
| Harness binding doesn't stop a process the agent starts inside the harness session, or the agent's user starting its own instance of the registered harness. | Both are legitimately below, or are, the registered program, running as the agent's user. | Run the harness under another user, or use a mandatory gateway. | [FAQ](faq.md#what-does-harness-binding-not-stop) |
| The LLM gateway's record is complete only when the agent can't reach the model around it. | The gateway sees only requests sent to it. | Let only the gateway reach the provider (network policy) and set `gateway_mandatory: true`. | [gateway](gateway.md#calling-it) |
| A tool the policy's `structured_output:` names gets no L3 cross-check: a decide for it needs no tool use in the model's response, and a tool use of it needs no decide, even under `gateway_mandatory`, so any tool of that name runs with no decide unseen. The browser pack names Browser Use's actions (`browser_use:*`) only; its output tool with Anthropic models (`AgentOutput`) is the deployment's to name. A child policy can't remove a name its parent declares. | Browser Use asks the model for its actions as structured output, which carries no tool use id to match a decide with. | Read Browser Use's records as decided by the signer, not as proven asked for by the model; declare only names whose calls really come as structured output and that no other tool of yours uses. | [gateway](gateway.md#reconciliation), [Browser Use](integrations/browser-use.md#the-browser-policy-pack) |
| **(1.2)** Tools the provider runs itself (web search, code execution, hosted MCP, ...) can't be held for a decision: they run mid-response. The gateway records their input where the provider returns it (not for image generation) and can only refuse a whole request that declares one (`provider_tools`). OpenAI `shell` and `tool_search` tools count as provider-run, since the provider may host them: with `allow`, list them if your client runs them. | No client-side step happens between the model asking and the provider running them, and a request doesn't always say who runs those two. | Deny provider tools you can't accept in gateway.yaml `provider_tools` (`mcp` covers every hosted MCP server, `mcp:<label>` one); the client gets a 403 naming them. | [gateway](gateway.md#provider-run-tools-12) |
| **(1.3)** Verified tool results catch an edited tool result for a call the signer already completed, and a result sent before its call completed. They don't catch text the agent adds outside tool results; a tool call the agent writes into the history itself with its result (reconciliation flags it at run.final, `result_without_call` or, under `gateway_mandatory`, `fabricated`, unless the agent also forges a decide, a result and a model report with `gateway_mandatory` off); results past a request's newest 512, which the agent chooses by adding results of its own; a request under the token of a run the agent registered itself; a result OpenAI Responses doesn't resend (`previous_response_id`) after its first send; and, with the signer unreachable and `model` failing open, a request the gateway forwards unchecked. | The check compares what the gateway sees against the signed results of the same run, by tool_call_id: content outside a tool result, a call with no result in that run, and a request never sent or never checked have nothing to compare with. | Set `gateway_mandatory` and let only the gateway reach the provider; keep the `model` class failing closed; read a run's `result_without_call` and `fabricated` records with its mismatches. | [gateway](gateway.md#verified-tool-results) |
| **(1.3)** Verified tool results are off unless signer.yaml sets `verify_tool_results`. A client whose recorded result isn't the value the model is sent mismatches on honest runs: they can't be used with the Claude Code hooks (a digest of the raw output) or the Claude Agent SDK integration (the structured tool response). Calls decided under ids of the client's own (the MCP integration, the MCP gateway) are unchecked, and so are calls completed with no result, error results and results whose content redaction changed. | Limit | Why it is so | What to do | Details |
|---|---|---|---|
| The `decide` RPC answers `allow` for a flagged call; only the signed `policy.decision` says `flag`. | `decision` tells the client what to do, and clients since RPC 15 know only `allow`, `deny` and `ask`; the signer can't tell a client's version. | Read a flag from the record, or from the flag rule's id in the response's `rule_ids`. | [policy](policy-v2.md#decisions) |

| The server pack's allowlists (`TK-N002`, `TK-B011`) name `example.com` until you redefine them. | Allowlists are deployment-specific. | Redefine those rules by id in your policy. | [policy](policy-v2.md#packs-shipped) |
| Parsed arguments that hold a lone surrogate (text typed or read from a broken page) are a signed deny, `TK-ARGS-INVALID`, not a decision on their content. | JSON can't carry a lone surrogate, so the client sends them as raw text, which isn't strict JSON. | Clean the text before the call, or expect the deny. | [policy](policy-v2.md#decisions) |
| Cloud-SDK-shaped tools other than CLIs and MCP tools aren't covered by the cloud pack. | Their argument shapes vary. | Map them under `tools` and add rules of your own. | [policy](policy-v2.md#packs-shipped) |
| The `payment` class doesn't extract `new_payee` yet. | Not built. | Match payees with your own rules. | [policy](policy-v2.md#classes-and-fields) |
| `unless` on a whole command line could exempt a different target. | The subject holds several targets. | Use `unless` only where the subject is one target. | [policy](policy-v2.md#what-a-rule-matches-the-subject) |
| v1 rules (`tracekit/policy/default.yaml`) match raw strings, so quoted text that mentions a risky command can trip them. | The v1 engine doesn't parse commands. | Use the v2 signer's policy; add exceptions for known false positives. | [evaluation](evaluation.md#e3-policy-gate) |

## Provenance (1.1)

| Limit | Why it is so | What to do | Details |
|---|---|---|---|
| **(1.1)** Provenance matches values verbatim: a value the model paraphrases, splits or re-encodes reads as a new value. | It is a tripwire on the commonest way injected instructions act, not information-flow control. | To prevent the flow, use information-flow control (CaMeL, FIDES) in the agent. | [policy](policy-v2.md#provenance-untrusted-and-from-untrusted) |
| **(1.1)** Only untrusted tools' results and observed inputs are indexed: a page fetched with a tool the policy doesn't list as untrusted (`curl` in a shell) isn't seen. | Results of other tools can echo the agent's own arguments, so they aren't counted either way. | List such tools under `untrusted`, or observe the content with `run.observe`. | [policy](policy-v2.md#provenance-untrusted-and-from-untrusted) |

| **(1.1)** Bare IPv6 addresses and integer IPs in text are not read as hosts (inside a URL they are). | Bare forms are ambiguous in prose. | Rely on the URL forms, or add rules of your own. | [policy](policy-v2.md#provenance-untrusted-and-from-untrusted) |

| The Browser Use adapter observes what the model read of each page (URL, title, tabs, text) up to 100,000 characters, from each browser state the session's `get_browser_state_summary` returns, which it wraps at the session's first action; the first step's state, made before that, comes from Browser Use's cached copy, which a tab closing before the first action empties. ## `tracekit last`

| Limit | Why it is so | What to do | Details |
|---|---|---|---|
| It pins the dev signer's key from the signer's own data dir, so the verdict is `dev` assurance. | The dev signer runs as your user.
